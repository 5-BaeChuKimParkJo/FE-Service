# 참여한 거래 · 경매별 입찰 내역

`/mypage/purchases`에서 동일 경매의 입찰을 한 카드로 묶는다. 내 최고 입찰가,
현재 가격, 입찰 횟수, 최근 입찰과 펼쳐 보는 시간순 기록을 제공한다.
제목 검색·상태 필터·최근 입찰순/내 입찰가 높은순 정렬·수동 새로고침을 지원한다.

기존 인증된 `GET /auctions/my-bids` 결과를 서버에서 경매 UUID별로 묶고 같은 경매의
중복 bidder UUID를 한 번만 센다. 높은 version의 경매 스냅샷을 사용하며 입찰은
시간 내림차순, 동률은 UUID로 정렬한다. 클라이언트에는 화면에 필요한 필드만 보낸다.
서버의 회원 프로필·상세 설명을 이 컴포넌트의 props로 보내지 않는다.

종료는 **종료**로 표시한다. 내 금액과 현재 금액이 같아도 낙찰·유찰로 판정하지
않는다. **상세 · 결제 확인**은 기존 경매 상세로 이동하며, 실제 낙찰자와 결제 권한은
기존 서버의 checkout 검증을 따른다. 목록을 읽거나 필터를 바꿀 때 주문 생성·결제·
정산·상태 확인 API를 실행하지 않는다.

빈 기록, 필터 결과 없음, API 오류를 구분한다. 필터 초기화와 오류 재시도를 제공하고
기본 KST 시각과 잘못된 날짜의 대체 표시를 사용한다. 기존 인증 middleware는 그대로다.

## 범위와 제약

요약 수치는 현재 API가 반환한 기록 기준이다. 기존 API가 제외하는 숨김·취소 경매를
복원하거나 전 계정 분석·서버 페이지네이션을 제공하지 않는다. 상태는 조회 시점의
서버 스냅샷이며 시간이 흐르면 수동 새로고침한다. 새 알림/실시간 서비스를 추가하지
않는다. 백엔드·DB·결제 계약·의존성·프론트 환경 설정 파일도 변경하지 않는다.

## 로컬 검증 · 2026-10-29

- 신규 요약/중복 제거·정렬·필터·상태·projection 테스트 7건 포함 전체 단위 89건 통과.
- frontend checker 테스트 11건과 실제 컨벤션 검사, 타입, 린트, 프로덕션 빌드 통과.
- 실제 Next 프로덕션 빌드와 로컬 fixture HTTP API로 데스크톱/모바일 6건 통과:
  중복 제거, 기록 펼치기, KST 순서, 검색/필터/초기화/정렬, 새로고침, 빈 기록,
  오류와 재시도 복구. 모든 fixture API 요청이 GET이고 checkout 조회도 없었다.
- 빈 화면의 기존 흰 글씨/투명 배경 버튼을 브라우저 테스트로 재현하고 해당 화면에만
  배경을 보완했다. amount 선택자가 숨겨진 기록과 겹친 테스트도 definition으로 좁혔다.
- 데스크톱/모바일 캡처를 직접 확인했다. 긴 제목에서 가로 넘침이 없고 disclosure,
  폼 라벨과 터치 영역을 제공한다. 기존 고정 헤더/하단 내비게이션 레이아웃은 유지한다.
- 로컬 Windows lint는 pnpm의 hoisted 모듈을 NODE_PATH로 지정해 검사했다.
  frozen offline 의존성 복구 때 기존 POSIX postinstall은 Git Bash로 실행했다.
  package.json/lockfile 변경은 없으며 기존 Next lint/Husky deprecation 경고는 남는다.

## 브라우저 검증 재현

첫 터미널에서 이 저장소의 빌드/서버를 실행한다. 별도 DB나 Docker는 필요 없다.

```powershell
$env:API_URL='http://127.0.0.1:34423'
$env:NEXT_PUBLIC_DEPLOYMENT_MODE='homelab'
pnpm build
pnpm exec next start -p 34725 -H 127.0.0.1
```

다른 터미널에서 실행한다. fixture API는 테스트가 시작/종료한다.

```powershell
$env:E2E_BASE_URL='http://127.0.0.1:34725'
pnpm exec playwright test e2e/my-bid-history.spec.ts --workers=1
```

fixture 토큰은 로컬 API만 받아들이는 문자열이다. 운영 자격 증명이나 실제 금융
요청이 아니며 운영 경매에 테스트 입찰을 넣어 결과를 만들지 않는다.
