# 관심 경매

경매 상세에서 **관심 등록 / 관심 해제**, 마이페이지에서 **관심 경매**로 이동한다.
목록 경로는 `/mypage/saved-auctions`다. 로그인한 계정의 PostgreSQL 데이터로
저장하므로 브라우저·기기가 바뀌어도 같은 계정으로 조회할 수 있다.

## 동작

- 대기·진행·종료 경매를 저장할 수 있다. 숨김·취소·삭제 경매는 목록에서 제외한다.
  다시 공개하면 이전 관심 등록이 보일 수 있다.
- 최근 등록 순으로 20개씩 보여주며 다음 페이지, 처음, 새로고침을 제공한다.
  가격·cursor는 정수 문자열을 유지하고 시각은 한국시간(KST)으로 표시한다.
- 서버 확인 후에만 등록 상태를 바꾼다. 최초 조회 오류는 미등록으로 간주하지 않고
  상태 재확인을 제공한다. 통신 실패 후 같은 동작을 재시도해도 중복 등록되지 않는다.
- 비회원은 공개 상세를 열람하고 로그인 링크를 사용한다. 개인 목록은 인증이 필요하다.
  클라이언트에는 회원 UUID·토큰 대신 화면에 필요한 경매 값만 전달한다.
- 목록·상태 조회와 변경은 캐시하지 않는다. 입찰·주문·결제·알림 API를 호출하지 않는다.
  상태·가격은 조회 시점 기준이며 실시간 갱신 대신 새로고침을 사용한다.

## 로컬 검증 · 2026-10-30

신규 action/정밀도/응답 검증 13건 포함 전체 단위 102건과 컨벤션 11건,
타입·린트·프로덕션 빌드를 통과했다. 실제 Next 프로덕션 서버와 로컬 HTTP fixture로
데스크톱·모바일 8건을 통과했다: 등록·새로고침 유지·개인 목록·해제, 알 수 없는 상태
재확인, 쓰기 오류 재시도·중복 클릭, 20개 cursor 페이지, 큰 금액, 목록 오류·빈 목록,
비회원 진입을 확인했다. 두 화면 크기의 캡처도 직접 확인했다.

Fastify는 JSON Content-Type만 있고 본문이 없는 DELETE를 400으로 거절한다.
해제 요청은 명시적 `{}`를 전송한다. 공유 fetch helper는 DELETE body 타입만 허용하며
기존 호출의 런타임 동작은 그대로다. action RED→GREEN, HTTP 계약과 fixture로 확인했다.

재현 시 첫 터미널에서 다음을 실행한다. fixture API는 브라우저 테스트가 관리한다.

```powershell
$env:API_URL='http://127.0.0.1:34424'
$env:NEXT_PUBLIC_DEPLOYMENT_MODE='homelab'
pnpm build
pnpm exec next start -p 34726 -H 127.0.0.1
```

다른 터미널:

```powershell
$env:E2E_BASE_URL='http://127.0.0.1:34726'
pnpm exec playwright test e2e/saved-auctions.spec.ts --workers=1 --retries=0
```

fixture 인증 문자열은 운영 자격 증명이 아니다. 운영 금융 요청이나 데이터 초기화를
실행하지 않는다. 실제 PostgreSQL 동시성·격리는 백엔드의 격리 DB CI에서 별도 검증한다.
