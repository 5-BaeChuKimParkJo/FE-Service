# 관심 경매

경매 상세에서 **관심 등록 / 관심 해제**, 마이페이지에서 **관심 경매**로 이동한다.
목록 경로는 `/mypage/saved-auctions`다. 로그인한 계정의 PostgreSQL 데이터로
저장하므로 브라우저·기기가 바뀌어도 같은 계정으로 조회할 수 있다.

## 동작

- 대기·진행·종료 경매를 저장할 수 있다. 숨김·취소·삭제 경매는 목록에서 제외한다.
  다시 공개하면 이전 관심 등록이 보일 수 있다.
- 최근 등록 순으로 20개씩 보여주며 다음 페이지, 처음, 새로고침을 제공한다.
  가격·cursor는 정수 문자열을 유지하고 시각은 한국시간(KST)으로 표시한다.
- 서버 확인 후에만 등록 상태를 바꾼다. 최초 조회 오류는 미등록으로 간주하지 않고
  상태 재확인을 제공한다. 통신 실패 후 같은 동작을 재시도해도 중복 등록되지 않는다.
- 비회원은 공개 상세를 열람하고 로그인 버튼을 사용한다. 개인 목록은 인증이 필요하다.
  클라이언트에는 회원 UUID·토큰 대신 화면에 필요한 경매 값만 전달한다.
- 목록·상태 조회와 변경은 캐시하지 않는다. 입찰·주문·결제·알림 API를 호출하지 않는다.
  상태·가격은 조회 시점 기준이며 실시간 갱신 대신 새로고침을 사용한다.

## 로컬 검증 · 2026-10-30

신규 action/정밀도/응답 검증 13건 포함 전체 단위 102건과 컨벤션 11건,
타입·린트·프로덕션 빌드를 통과했다. 실제 Next 프로덕션 서버와 로컬 HTTP fixture로
데스크톱·모바일 10건을 통과했다: 등록·새로고침 유지·개인 목록·해제, 알 수 없는 상태
재확인, 쓰기 오류 재시도·중복 클릭, 20개 cursor 페이지, 큰 금액, 목록 오류·빈 목록,
비회원 진입을 확인했다. 두 화면 크기의 캡처도 직접 확인했다.

Fastify는 JSON Content-Type만 있고 본문이 없는 DELETE를 400으로 거절한다.
해제 요청은 명시적 `{}`를 전송한다. 공유 fetch helper는 DELETE body 타입만 허용하며
기존 호출의 런타임 동작은 그대로다. action RED→GREEN, HTTP 계약과 fixture로 확인했다.

독립 리뷰에서 만료/무효 쿠키가 남은 AUTH_REQUIRED의 단순 링크는 기존 middleware에
의해 홈으로 튕기는 Important 1건을 확인했다. 실제 브라우저 2건의 실패를 재현한 뒤
기존 signOut으로 accessToken·refreshToken·memberUuid를 삭제하고 로그인으로 이동하도록
수정했다. 상세와 개인 목록 양쪽에서 복구·쿠키 제거를 확인해 전체 10건이 통과했다.
초기 HTML에서 이벤트 연결 전 클릭이 유실되지 않도록 준비 후 버튼을 활성화한다.
비회원 로그인과 기존 공개 상세 정책도 검증한다. JWT 검증·자동 세션 갱신은 변경하지 않는다.

리뷰의 Critical/Minor는 없었다. 기존 인증/결제 전체와 상세 API 숫자 표현은 유지한다.
그 영역의 기존 장애나 큰 금액 반올림은 이 목록이 해결하지 않는다. 동시 삭제 중의
페이지 구성 변화와 공유 체험 계정의 공동 관심 목록도 제한 사항으로 유지한다.

재현 시 첫 터미널에서 다음을 실행한다. fixture API는 브라우저 테스트가 관리한다.

```powershell
$env:API_URL='http://127.0.0.1:34424'
$env:NEXT_PUBLIC_DEPLOYMENT_MODE='homelab'
pnpm build
pnpm exec next start -p 34726 -H 127.0.0.1
```

다른 터미널:

```powershell
$env:E2E_BASE_URL='http://127.0.0.1:34726'
pnpm exec playwright test e2e/saved-auctions.spec.ts --workers=1 --retries=0
```

fixture 인증 문자열은 운영 자격 증명이 아니다. 운영 금융 요청이나 데이터 초기화를
실행하지 않는다. 실제 PostgreSQL 동시성·격리는 백엔드의 격리 DB CI에서 별도 검증한다.

## 실제 CI · 2026-10-30

3건은 별도 로컬 프로덕션 Next/fixture 실행 근거이며 CI 실행 항목과 구분한다.

백엔드 `d70874936f8491c8a3de15ba0b4db5cdee0788fd`의 전체 CI가 먼저 통과했다.
신규 관심 저장 7건 포함 PostgreSQL 62건과 실제 Kafka 4건을 확인했으며,
운영의 additive migration 완료·새 이미지 준비·Argo 정상 이후 이 FE를 게시했다.

## 운영 확인 · 2026-10-30

자동 GitOps `9ed5ec4de7c2a1b1fd57a47960edd5facd1fcb65`가 frontend 이미지 `93eeb2e`를
반영했다. 처음 25초의 준비 대기는 만료됐고 이후 실제 rollout 완료, 새 파드 Ready·
재시작 0, 이전 프론트 파드 종료, Argo Synced/Healthy를 확인했다.

기존 공개 체험 로그인으로 다음을 확인했다. 쿠키·토큰은 메모리에만 두고 출력하거나
파일로 저장하지 않았다. 기존에 미등록인 공개 경매를 골라 기존 관심 항목은 수정하지 않았다.

- 비회원의 개인 목록은 로그인으로 이동했다.
- 상세에서 등록하고 페이지를 새로고침해도 등록 상태가 유지됐다.
- 같은 로그인 상태의 별도 데스크톱·모바일 브라우저 컨텍스트에서 목록 카드가 표시됐다.
  수동 새로고침, 가로 넘침 없음도 확인했다.
- 모바일 목록에서 해제하고 페이지 재로딩 후 사라진 것을 확인했다. 상세도 미등록으로
  돌아왔으며 마지막에 기존 미등록 상태가 복구된 것을 재조회했다.
- 브라우저에서 입찰·결제·이미지 업로드 POST는 0건이었다.

운영에서 통신 장애·토큰 만료를 강제로 만들지는 않았다. 그 복구 경로와 20개 초과
페이지·큰 금액·소유자 격리·실제 DB 동시성은 위 fixture/통합 테스트 근거다.
