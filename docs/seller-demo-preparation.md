# 판매자 데모 준비

판매자 체험 계정으로 로그인한 뒤 **내 경매 → 판매자 데모 준비**를 누릅니다.
수정 가능한 본인 데모가 있으면 해당 관리 화면으로 이동하고, 없으면 대기 경매 하나를 준비합니다.
새 경매는 1,000원으로 시작하며 시작 시각은 UTC 정시 기준 1~2시간 뒤, 진행 기간은 24시간입니다.

일반 계정과 구매자 체험 계정에는 버튼을 표시하지 않습니다. 서버는 JWT의 본인 UUID를
설정된 판매자 UUID와 비교하며 요청 본문으로 계정이나 템플릿을 선택할 수 없습니다.
FE에는 판매자 자격 증명이나 템플릿 설정을 전달하지 않습니다.

## 중복 요청과 실패

- 버튼은 초기화 중과 요청 중 비활성화하고 빠른 연속 클릭도 한 번만 전송합니다.
- 서버는 동일 템플릿 준비 요청을 직렬화하고 수정 가능한 데모를 재사용합니다.
  이름을 바꾼 데모도 생성 출처로 확인합니다.
- 새 데모 생성은 1분 간격입니다. 직전 데모를 취소하거나 삭제해도 간격을 우회하지 못합니다.
  수정 가능한 데모 재사용에는 생성 간격을 적용하지 않습니다.
- 응답이 유실되어도 자동으로 다시 생성하지 않습니다. 내 경매를 확인하거나 직접 다시 준비하면
  서버에 남은 수정 가능 데모를 재사용합니다.
- 시작·입찰·구매·결제 등으로 수정이 제한된 경매와 기존 기록은 초기화하지 않습니다.

## 검증과 배포

로컬 단위 테스트 146건, 캐시 없는 린트, 타입 검사와 프로덕션 빌드가 통과했습니다.
프로덕션 Next 서버와 격리된 HTTP fixture를 사용한 PC·모바일 브라우저 테스트 18건이 통과했습니다.
신규 10건은 생성·재사용·연속 클릭·응답 유실 후 명시적 재시도·쿨다운·계정별 표시를,
기존 8건은 내 경매 조회 회귀를 확인합니다. PC·모바일 화면도 확인했습니다.
이 검증은 실제 PostgreSQL 동시성 검증이나 운영 반영 증거를 대신하지 않습니다.

백엔드·설정을 먼저 배포하고 해당 이미지가 준비된 뒤 프론트를 배포합니다.
실제 서버에서는 버튼으로 최대 한 건을 준비한 뒤 PC와 모바일에서 같은 UUID 재사용을 확인합니다.
운영 경매 수정·취소·입찰·결제·업로드는 검증 과정에 포함하지 않습니다.

백엔드 계약과 동시성 검증은 `../node-service/docs/seller-demo-preparation.md`,
설정과 운영 절차는 `../cncn_private/docs/runbooks/seller-demo-preparation.md`를 참조합니다.
