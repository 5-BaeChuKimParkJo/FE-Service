# 판매자 데모 준비

판매자 체험 계정으로 로그인한 뒤 **내 경매 → 판매자 데모 준비**를 누릅니다.
수정 가능한 본인 데모가 있으면 해당 관리 화면으로 이동하고, 없으면 대기 경매 하나를 준비합니다.
새 경매는 1,000원으로 시작하며 시작 시각은 UTC 정시 기준 1~2시간 뒤, 진행 기간은 24시간입니다.

일반 계정과 구매자 체험 계정에는 버튼을 표시하지 않습니다. 서버는 JWT의 본인 UUID를
설정된 판매자 UUID와 비교하며 요청 본문으로 계정이나 템플릿을 선택할 수 없습니다.
FE에는 판매자 자격 증명이나 템플릿 설정을 전달하지 않습니다.

## 중복 요청과 실패

- 버튼은 초기화 중과 요청 중 비활성화하고 빠른 연속 클릭도 한 번만 전송합니다.
- 서버는 동일 템플릿 준비 요청을 직렬화하고 수정 가능한 데모를 재사용합니다.
  이름을 바꾼 데모도 생성 출처로 확인합니다.
- 새 데모 생성은 1분 간격입니다. 직전 데모를 취소하거나 삭제해도 간격을 우회하지 못합니다.
  수정 가능한 데모 재사용에는 생성 간격을 적용하지 않습니다.
- 응답이 유실되어도 자동으로 다시 생성하지 않습니다. 내 경매를 확인하거나 직접 다시 준비하면
  서버에 남은 수정 가능 데모를 재사용합니다.
- 시작·입찰·구매·결제 등으로 수정이 제한된 경매와 기존 기록은 초기화하지 않습니다.

## 검증과 배포

로컬 단위 테스트 146건, 캐시 없는 린트, 타입 검사와 프로덕션 빌드가 통과했습니다.
프로덕션 Next 서버와 격리된 HTTP fixture를 사용한 PC·모바일 브라우저 테스트 18건이 통과했습니다.
신규 10건은 생성·재사용·연속 클릭·응답 유실 후 명시적 재시도·쿨다운·계정별 표시를,
기존 8건은 내 경매 조회 회귀를 확인합니다. PC·모바일 화면도 확인했습니다.
실제 DB 검증은 별도 격리 CI에서 수행했고, 운영 반영은 아래 실제 서버 결과로 확인했습니다.

2026-11-01 백엔드·설정을 먼저 배포하고 해당 이미지 Ready 후 프론트를 배포했습니다.
[백엔드 CI](https://github.com/5-BaeChuKimParkJo/node-service/actions/runs/41256544581)는
단위 479건, 별도 PostgreSQL 통합 109건(신규 준비 동시성 18건 포함), 실제 Kafka 4건을 통과했습니다.
단위 단계의 보호된 DB·Kafka skip 112건은 통합 성공 수에 포함하지 않습니다.
[프론트 CI](https://github.com/5-BaeChuKimParkJo/FE-Service/actions/runs/41257108763)는
단위 146건, 컨벤션 11건, 타입 검사와 프로덕션 빌드·이미지 발행을 통과했습니다.

GitOps 이미지 커밋은 BE `5291521`, FE `eafb333`이고 각 매니페스트 CI도 통과했습니다.
실제 이미지는 BE `0166f1d`, FE `cea999d`입니다. 두 파드 Ready, 재시작 0,
롤아웃 성공 및 Argo CD `Synced / Healthy`를 확인했습니다.

실제 판매자 버튼으로 대기 경매 `12c8e7f5-01c6-4bf1-aff8-16e8a7f1210d` 한 건을 생성했습니다.
PC의 두 번째 클릭과 모바일 클릭은 같은 UUID를 재사용했고 수정 폼이 활성화됐습니다.
시작가 1,000원, 입찰 0건, 정각 시작·24시간 진행, 빈 변경 이력을 확인했습니다.
기존 경매 3건의 제목·설명·금액·일정·버전·변경 이력은 그대로였습니다.
구매자 계정은 버튼 부재·준비 POST 403을 확인했습니다. 검증 중 결제·입찰·업로드 POST는 0건이며
기존 경매 수정·취소·초기화는 수행하지 않았습니다. 데모 일정은 실제 시간에 따라 진행됩니다.

백엔드 계약과 동시성 검증은 `../node-service/docs/seller-demo-preparation.md`,
설정과 운영 절차는 `../cncn_private/docs/runbooks/seller-demo-preparation.md`를 참조합니다.

## 리뷰와 판단 범위

BE `0166f1d`, FE `cea999d`, GitOps `78ebddc`의 전체 변경을 한 번 독립적으로
읽기 전용 리뷰했습니다. Critical·Important·Minor 지적은 없었습니다.
리뷰어가 판단을 유보한 실제 DB 동작은 격리 CI로, 운영 설정·이미지·화면은 위의 실제
버튼 확인으로 검증을 마쳤습니다. 리뷰 결과 자체를 실행 검증의 대용으로 취급하지 않았습니다.

템플릿 변경 중의 범용 보장, 계정 전체 남용 방지와 영구 요청 키 멱등성은 이번 범위에서
제외하기로 판단했습니다. 비용은 보장 범위가 고정 템플릿과 수정 가능 자원 재사용에
한정된다는 점입니다. 운영자가 템플릿을 교체할 때에는 유효한 본인 소유 원본을
설정해야 합니다. 새 데모 1분 간격은 이 준비 API에만 적용됩니다.
