# 대기 경매 수정·취소

내 경매의 **경매 관리**에서 제목·설명·시작가·시작/종료 시각을 수정하거나 출품을 취소한다.
사진·카테고리·태그·거래 방식은 이번 범위에서 변경하지 않는다. KST 정각 일정, 최소1시간,
제목5–100자/설명1000자, 시작가1000~2147483647원으로 기존 검색 int 범위를 사용한다.

취소 사유는 등록 정보 오류/상품 판매 불가/경매 일정 변경/개인 사정/기타다. 기타만 수기
설명1–200자를 받는다. 취소 확인 후 상태를 바꾸며 삭제하지 않고 최근20건의 판매자 변경
이력에 시각·사유·이전/변경 값을 남긴다. 이미 시작했거나 입찰·거래·숨김·취소 상태면 조회만 한다.

기존 관리자 PUT을 확대하지 않고 `/auctions/:uuid/seller` GET/PATCH와 `.../cancel` POST를
사용한다. JWT 소유자만 접근하고 다른 사람/삭제 경매는404다. 공개 legacy PUT/DELETE는
관리자로 제한했다. 기존 클라이언트가 판매자 DELETE를 사용했다면 새 취소 경로로 이전해야 한다.
내부 거래 완료 호출은 변경하지 않는다.

서버는 행 잠금 이후 상태와 버전을 다시 확인한다. DB 시계가 시작 시각을 넘은 경우 SQL
조건부 UPDATE도 거부한다. 이전 버전이나 중복 요청은409이며, 화면은 최신 상태를 다시
확인하도록 안내한다. 요청 시간 초과는 실패로 단정하거나 자동 재시도하지 않는다.
성공 후 문서 탐색으로 서버 상태와 이력을 새로 읽는다. 취소 상태와 이력·Outbox는 같은
트랜잭션에 기록되고, 기존 검색 삭제 이벤트를 사용한다. 실제 입찰·결제를 만들지 않는다.

## 로컬 재현

운영 자격 증명이나 DB를 복사하지 않는다. fixture 전용 API를 사용해 빌드/실행한다.

```powershell
$env:API_URL='http://127.0.0.1:34427'
$env:NEXT_PUBLIC_DEPLOYMENT_MODE='homelab'
$env:COOKIE_SECURE='false'
pnpm build
pnpm exec next start -p 34729 -H 127.0.0.1
```

다른 터미널:

```powershell
$env:E2E_BASE_URL='http://127.0.0.1:34729'
pnpm exec playwright test e2e/seller-management.spec.ts --workers=1 --retries=0
```

fixture에서만 수정·취소를 실행한다. 운영 검증은 기존 판매자 샘플과 구매자의 읽기 접근을
확인하며 기존 경매·입찰·결제·이미지를 초기화하지 않는다.

링크를 각각 확인하도록 수정했다. 공개 접근이나 앱 동작을 완화한 변경은 아니다.

## 리뷰 보완과 운영 판단

단일 리뷰의 Important2건을 실제 코드에서 확인해 실패 테스트로 재현했다. 기존 Kafka
일괄 입찰 처리가 취소 상태를 검사하지 않아 재색인할 수 있던 경로는 행 잠금 이후에
보호 상태·시각을 검사한다. 취소/숨김/삭제/거래 보호 상태는 입찰·가격·이벤트를 쓰지
않으며 종료 시각은 미포함이다. 별도 서비스·검색 인덱스 변경은 추가하지 않는다.

검색 consumer와 ES 매핑이 int여서 시작가 상한은2147483647원이다. 기존 초과 가격은
정상 수정 후 취소해야 하며 UI에서 안내한다. 실제 이벤트 값을 임의로 줄이지 않는다.
이 선택의 비용은 가격 상한과 일부 기존 출품의 추가 정정 단계다.

보류된 Minor: 변경할 수 없는 경매 화면의 현재 설명·시작 시각 표시는 추후 보완한다.
API는 해당 값을 제공하지만 현재 UI는 제목·가격·마감과 이력을 보여준다.

리뷰 보완 후 최종 로컬 기준은 backend 단위459건과 보호된94 skip, 네 앱 빌드·검사기,
frontend133건·타입/린트/빌드, 프로덕션 브라우저16건과 기존 목록 회귀8건이다.
Kafka 상태 검사/잠금 후 시각/가격 범위 실패8건과 프론트 가격 실패를 먼저 확인했고,
기존 초과 가격 취소 UI도 실패 후 통과했다. 기존 입찰 mock의 필수 상태 누락1건과
자기 입찰 테스트가 종료 정각에 놓여 있던2건은 fixture를 맞췄으며 보호 검사를 풀지 않았다.

리뷰는 정적 검토이며 실제 검사·CI·격리 PG/Kafka·화면·배포 증거는 작성자가 확인한다.
전체 Kafka/CDC/Elasticsearch 장애 복구·재생·수렴과 운영 부하·잠금 시간은 이번 결과로
인증하지 않는다. 렌더 검증은 현재 PC·모바일 브라우저 범위이며 종합 접근성 감사가 아니다.
기존 인증·관리자·결제·내부 완료의 전반적인 정합성은 재검증 범위에서 제외한다.

## 판단의 검증 한계

- 정적 리뷰는 실행 결과를 독립 재실행하지 않았다. 검사·캡처·CI·격리 DB와 실제 읽기
  검증은 작성자의 실행 증거다. 독립 실행 확인이 추가되지는 않았다.
- 격리 DB의 경합·롤백 성공은 실제 CI 범위다. 보호된 skip이나 운영 규모의 검증으로
  대체하지 않았으며, 대규모 잠금 지연·부하·운영 데이터 변경은 측정하지 않았다.
- 취소 후 Kafka DB 회귀와 기존 실제 Kafka 복구 검사를 수행했지만, 전체 CDC/ES 장애
  복구·재생·수렴을 새로 인증하지 않았다. 별도 검색 운영 검증 비용은 남는다.
- migration→백엔드 Ready→프론트 순서와 실제 소유자·구매자·legacy 거부는 확인했다.
  실서버 대기 경매 저장·취소는 실행하지 않았으며 해당 동작은 격리 환경의 증거다.
- 렌더 검증은 현재 PC·모바일 브라우저에 한정한다. 포괄적 접근성 감사가 아니며,
  기존 인증·관리자·결제·내부 완료 전반의 정확성을 이번 기능이 보증하지 않는다.
